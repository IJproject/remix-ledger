## 進め方

1 機能ずつ「ドメインの型 → DB → 画面」まで作り切って動かし、それを繰り返す。

1. 該当する節を読む
2. 「やりたいこと」を書く（下のテンプレート）
3. 実装案（ドメインの型・テーブル・routes）を出してもらう
4. 実装案をレビューする（本の考え方と照らし合わせる）
5. 実装する（implement-workflow: PLAN.md → Codex → レビュー）
6. 動かして確認し、気付いたことをこのファイルに反映する

### 「やりたいこと」テンプレート

```
- やりたいこと:
- 本の該当箇所:
- 具体例: （例: 3/1 文房具を現金で 1,100円 購入 → 借方 消耗品費 1,100 / 貸方 現金 1,100）
- ルール:
- やらないこと:
```

## 設計方針（決定済み）

- DB は PostgreSQL（Docker Compose で起動）
- 金額は TS では `number`、DB では円単位の整数（`integer`）で持つ
  - 小数は扱わない（外貨会計に取り組むときに見直す）
  - `integer` の上限は約 21 億。SQL の `sum()` の結果は `bigint` になり、ドライバからは文字列で返ってくる点に注意
