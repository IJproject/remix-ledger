# コーディング規約

## コメント

コメントには、ソースコードを読んでも分からないことだけを書く。見本は `app/domain/account/model/primitive.ts`。

### 書くもの

- なぜその形にしたのか（決定の背景。ほかの案を選ばなかった理由があればそれも）
- 守らないと壊れる前提や、ハマりやすい罠（例: 単一プロセス前提で起動時にマイグレーションを流す）
- 型や名前に表れない約束（例: 一覧のポートはコードの昇順で返す）
- 定数の値の根拠（業務の仕様なのか、仮に決めた値なのか）

### 書かないもの

- 名前と型を読めば分かること。ワークフローの型は接尾辞で役割が分かるので、コメントを付けない

  | 接尾辞 | 役割 | 例 |
  | --- | --- | --- |
  | `Command` | ワークフローへの入力 | `RegisterAccountCommand` |
  | 過去形 | ワークフローが出すイベント | `AccountRegistered` |
  | `Error` | 失敗の理由 | `RegisterAccountError` |
  | `Workflow` | ワークフローの型 | `RegisterAccountWorkflow` |
  | `Ports` / `Port` | ワークフローが外に求める関数 | `RegisterAccountPorts`, `InsertAccountPort` |

- 処理をそのまま日本語に言い換えただけのもの（例: `validateAccount` に「入力を検証する」）
- テストの `/** @see {@link ...} */` は、テスト対象の定義へジャンプするためのリンクなので残してよい
